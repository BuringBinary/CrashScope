# CrashScope 深色 UI 与双语言适配评估

- 日期：2026-09-20
- 代码基线：`71c0603`，分支 `feature/local-desktop-work`
- 结论：建议重构 UI 主题资源与公共控件层，不建议重写整个桌面端、双语言机制或采集/诊断核心。
- 状态：评估与方案，尚未实施 UI 改造。除本评估文档外，本轮未修改仓库文件。

## 1. 范围与验证边界

已检查 `src/CrashScope.Desktop` 的主题服务、语言服务、应用资源入口、两套主题字典、主窗口、设置页、图表及部分辅助窗口。当前已有 `Locales/zh-CN.json`、`Locales/en-US.json` 和独立的 `LocalizationService`，语言资源与主题资源并非必须一起推翻。

本结论来自源码审查和色值计算，不是实际运行界面的截图验收。未更改用户语言/主题配置、Windows 设置或录制状态，未运行构建、测试、安装、发布或应用重启。用户提到的具体难读界面仍应通过截图或应用内验收进一步确认。

C# LSP 引用查询返回 `semantic_result_inconclusive=true`，因此改用有范围的文本检索；没有把空语义结果当作符号不存在。颜色检索设置了单文件上限，命中数量不是全项目硬编码总数。

## 2. 主要发现

### F1. 八位颜色值与 WPF 的 ARGB 顺序不匹配

证据：`src/CrashScope.Desktop/Themes/DarkTheme.xaml:23,90,217`、`src/CrashScope.Desktop/Themes/LightTheme.xaml:23,88`、`src/CrashScope.Desktop/Pages/DashboardPage.xaml:30,86,160`。

WPF 八位十六进制颜色按 `#AARRGGBB` 解析，不是网页常见的 `#RRGGBBAA`。

- 导航选中背景 `#6C5CE722` 实际是透明度 `6C`、RGB `5CE722`，并非透明度 `22` 的紫色 `6C5CE7`。
- 如果目标是上述半透明紫色，应使用 `#226C5CE7`；更稳妥的是明确的颜色资源配合透明度，而不是继续散落八位字面量。
- 仪表盘 `#00D68F22` 的 WPF 透明度实际为零；`#FF6B6B22` 则完全不透明。这些是可确认的解析结果，最终设计意图仍需对照视觉目标确定。

按当前导航样式推算，未悬停的选中背景覆盖 `SidebarBg=#1A1B2E` 后约为 `#367129`，选中文字仍为 `#6C5CE7`，形成很差的可读性组合。

### F2. 主题热切换只覆盖了一部分界面

证据：`src/CrashScope.Desktop/Services/ThemeService.cs:99-117`、`src/CrashScope.Desktop/MainWindow.xaml:24-25,51-63,95-178`、`src/CrashScope.Desktop/Pages/SettingsPage.xaml:81-85`。

主题服务通过移除旧字典、加入新字典切换主题。页面上的许多背景/文字已经使用 `DynamicResource`，这是可以保留的基础；但主窗口仍有 16 处显式 `Style="{StaticResource ...}"`，所引用的主题样式内部又保存了固定色值。

替换字典不会让已通过静态引用取出的旧样式自动变成新样式，因此存在旧按钮/导航样式与新背景混用的问题。主窗口渐变的颜色键也仍是静态引用。源码范围内未找到 `ThemeChanged` 的订阅者，只有事件声明和触发；实际切换表现还需在运行界面确认。

修复方向不是机械地将所有 `StaticResource` 替换掉。应优先让两种主题共享同一套控件模板，模板中的颜色使用动态语义资源；不会随主题改变的结构模板仍可使用静态引用。

### F3. 公共控件样式重复，覆盖范围不完整

证据：`src/CrashScope.Desktop/Themes/DarkTheme.xaml`、`src/CrashScope.Desktop/Themes/LightTheme.xaml`、`src/CrashScope.Desktop/Themes/CommonResources.xaml`、`src/CrashScope.Desktop/RawSensorWindow.xaml:18-55`。

两套主题各自定义了相同的 9 类顶层样式，包括标题栏、导航、按钮及 ComboBox。公共资源目前主要是图标/文本模板，还未承担统一控件样式的职责。主题内定义的部分语义色键没有被对应模板引用，改色板不一定能改变控件。

ComboBox 已有自定义主题模板，不能说它完全未适配。但 TextBox、CheckBox、ListView 表头、滚动条等没有在这三份主题资源中获得同等覆盖；辅助窗口仍依赖部分系统默认控件外观。按钮/导航模板也缺少完整的按下、禁用及键盘焦点视觉状态。

### F4. 图表与代码生成的颜色未统一接入主题

证据：`src/CrashScope.Desktop/Pages/DashboardPage.xaml.cs:55-63,144-178`、`src/CrashScope.Desktop/MainWindow.xaml.cs:85-90`、`src/CrashScope.Desktop/Pages/RecorderStatusPage.xaml.cs:42-81`。

OxyPlot 的网格/刻度/文本颜色是静态常量，坐标文字字号为 9，不能单靠 XAML 色板切换完成适配。其他状态颜色也有代码内固定赋值。图表还保留 `Seconds ago` 等英文字符串，相关界面改造时应补做中英文回归，而不是重写已有语言服务。

### F5. 当前没有跟随 Windows 主题的模式

证据：`src/CrashScope.Desktop/Services/ThemeService.cs:20-23,38-55,108-113`、`src/CrashScope.Desktop/Pages/SettingsPage.xaml.cs:164-194`。

当前只有 `Dark`、`Light`，初始默认值为 `Dark`。不能把“Windows 已设为深色”视为应用已经完整跟随系统主题。后续可增加“跟随系统 / 浅色 / 深色”，并单独处理高对比度模式；这属于待实施能力，而不是现有功能。

### F6. 双语言与小窗口布局有相邻风险

证据：`src/CrashScope.Desktop/MainWindow.xaml:7,70,95-178`、`src/CrashScope.Desktop/Themes/DarkTheme.xaml:74-75`、`src/CrashScope.Desktop/Pages/SettingsPage.xaml:81-85`、`src/CrashScope.Desktop/Locales/en-US.json:388-389`。

主导航是 13 个固定高度 40 的项目，外层未设置滚动容器，而窗口允许缩到高度 600；需要验证底部项目在小窗口中的可达性。设置页部分按钮固定宽度 120，模板左右内边距各 16，英文 `Open incidents folder` 等长文案容易挤压。这里只确认结构风险，未声称已完成运行时溢出测量。

## 3. 对比度静态估算

方法：将前景/背景按 sRGB 计算相对亮度；半透明导航背景先按当前底色合成。数值是源码条件下的估算，不是实际像素测量，也不代表完整无障碍认证。

| 组合 | 估算对比度 | 解读 |
| --- | --- | --- |
| 主文字 / 卡片底色 | 13.13:1 | 并非所有深色文字都有问题 |
| 次文字 / 卡片底色 | 4.80:1 | 达到普通文字常用的 4.5:1 基线；小字号仍需实看 |
| 导航选中文字 / 实际 ARGB 合成背景 | 1.21:1 | 应优先修复 |
| 导航选中文字 / 悬停底色 | 2.80:1 | 普通字号文字仍不足 |
| 卡片底色 / 内容底色 | 1.19:1 | 视觉层次较弱；装饰底色不等同于控件边界合规要求 |
| 控件边框 / 卡片底色 | 1.18:1 | 需要检查是否足以识别交互边界 |

## 4. 建议的改造边界与顺序

### 第一阶段：主题基础与样板界面

1. 修正/明确八位颜色的透明度顺序，并为导航选中态配置成对的前景和背景资源。
2. 保留现有深浅主题入口，将颜色收敛为背景、卡片、浮层、正文、次文字、边框、强调色、状态色等语义键。
3. 抽出一套共享控件样式，消除两套主题内重复维护模板的情况；颜色使用动态资源。
4. 以主窗口、导航和设置页作为样板，补齐普通、悬停、按下、选中、禁用和键盘焦点状态。
5. 保留现有标题栏命中测试设置、图标与中英文文本分离模板，避免重新引入窗口按钮失效或字体方框问题。

视觉方向建议：更中性的深灰背景、可辨认的卡片/浮层层级、清晰的主次文字，紫色仅用于强调和选中提示，不让小字号长文本承担低对比度强调色。

### 第二阶段：页面、图表与系统适配

1. 按页面迁移硬编码背景与状态色，包含辅助窗口和弹出内容。
2. 为 OxyPlot 增加统一主题适配，在 UI 线程更新文本、轴线、网格及必要的系列颜色并刷新绘图，不清空采样历史；正确注销事件以避免页面泄漏。
3. 明确悬浮条是否独立固定深色。现有半透明暗色悬浮条不应未经确认就当作错误强制改掉。
4. 增加可选的跟随系统模式，区分用户偏好和实际生效主题，并尊重系统高对比度设置。

### 第三阶段：可读性与双语言回归

1. 统一正文、辅助文字、图表刻度的字号与间距，优先消除关键内容使用过小字号的情况。
2. 为导航提供小窗口下的滚动可达性；长按钮文本采用合理的最小宽度、自适应布局或换行策略。
3. 保留现有语言资源和业务逻辑，仅补齐本轮涉及界面的未本地化文本。

不建议在本轮更换 UI 框架、大规模搬迁业务代码、修改采集/诊断协议或重写本地化服务。

## 5. 验收标准

- 普通重要文本以前景/背景对比度至少 4.5:1 为设计基线；必要的交互边界及焦点提示以 3:1 为参考，不能把装饰性分隔一律当作强制边界。
- 已打开的主窗口、设置页、弹出列表和图表切换深浅主题后，无残留旧主题颜色，不依赖重启。
- 中英文 × 深浅主题 × 100%/125%/150% 缩放 × 默认/最小窗口尺寸检查布局；重点检查导航底部、长按钮、表头、图表刻度及提示文字。
- 验证鼠标与键盘的选中、悬停、按下、禁用和焦点状态；状态不能只用颜色表达。
- 建立资源键一致性、关键颜色组合及主题切换测试；UI 测试应使用隔离配置，不改写真实用户设置。
- 改造后执行构建、诊断及相关测试，并做真实窗口截图对照；本评估阶段未执行这些验收项。
- 不为主题验证中断正在进行的录制或长时间采集；需要影响正在运行应用的操作时先取得确认。
