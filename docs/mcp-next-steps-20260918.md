# CrashScope 后续实施规划

日期：2026-09-18。本文为建议计划，不代表已授权或已执行后续采集、提权和系统配置变更。

## 基线与目标

基于 `docs/mcp-upgrade-acceptance-20260918.md`：0.9.1.0 已完成短时普通权限实机验收，主会话 324 条、重启会话 37 条，最终正常停止，保留新版窗口。137 文件备份及 131 个既有会话/事件证据文件已校验。当前仍存在系统 ETW 权限错误、CPU 部分读数不可用、磁盘指标缺失，以及 GPU ETW 事件覆盖未验证。

下一阶段目标不是把所有状态变绿，而是确认哪些证据可信、哪些明确不可用，并让下一次问题发生时留下足够的判别材料。短时正常录制不等于整机故障已修复。

## P0：明确故障现象与保护基线

- 确认历史 09:07、09:16 两次究竟是整机卡死、黑屏后恢复、仅 CrashScope 退出，还是用户主动结束进程。
- 补充发生时的操作、时间、鼠标/声音/远程连接是否响应、是否必须长按电源，以及是否存在蓝屏或转储文件。
- 将现象描述与已有事件、日志时间线关联，不根据历史 cleanShutdown=false 或空 ETW 文件直接判定 HardFreeze。
- 保留当前独立包、备份、验收报告；后续代码修复使用新的版本和独立目录，不覆盖本次基线。

验收标准：形成明确的故障类型与复现条件记录；没有信息时保持 Unclassified，并明确缺失信息。

## P1：采集链路专项诊断与修复（下一步首选）

### 1. ETW：区分启动成功与事件覆盖

- 针对每个 provider 记录启用结果、错误码、已接收/已写入事件数、最后事件时间，以及可获得的事件丢失统计。
- 区分 Started、Observed、Error 等语义；没有事件时保留“尚未观察到匹配事件”，不要假装健康，也不要自动认定故障。
- 对普通权限下 E_ACCESSDENIED 给出具体采集器和权限提示，禁止循环静默重试或自动提权。
- 在适用 provider 上，用温和、已知会产生目标事件的活动做对照；不注入 WHEA/硬件错误，不以制造故障来证明采集器存活。
- 如果确实需要管理员权限，只在用户单独授权后做一次明确范围的对照实验；不默认常驻管理员或安装服务。

验收标准：能够解释“启用失败”“已启用但未观察到事件”“确实收到并写入事件”的差别，界面与持久化健康记录一致。

### 2. CPU 与磁盘：确认数据源能力边界

- 只读核实硬件、权限、驱动和数据源支持情况，区分 Unsupported、PermissionDenied、Error 和暂时 NoData。
- CPU 缺失温度、频率等字段继续显示 N/A；不可把无效零值当作真实测量。
- 核查磁盘枚举和指标获取路径；评估已有 Windows 数据源能否提供所需指标，避免为消除提示就更换驱动。
- 任何替代数据源都记录来源、单位、采样时间和有效性，不能混淆不同指标定义。

验收标准：支持的指标可重复采集；不支持的指标具有可解释的原因；存储记录存在但没有磁盘指标时仍应明确提示 NoData。

### 3. GPU：修正进程显存统计口径

- 评估以 PID + adapter/LUID + 内存类型保留原始维度，避免独显、集显或不同统计来源直接相加后与单卡容量比较。
- 明确不同数据源和工具的显存定义，不能因为数值不一致就认定其中一方错误。
- 在口径、容量归属和时间对齐未验证前，不恢复“显存耗尽”的因果评分。

验收标准：每个显存数值可追溯到适配器、类型和来源；重复计数、跨适配器混算有测试覆盖。

实施顺序：先做只读诊断和最小修复方案，再修改代码、回归测试和发布新的独立测试包。诊断结论可能是明确标为不可用，而不是保证所有指标都能采到。

## P2：中时稳定性与资源开销验收

P1 达到可解释的采集状态后，另行确认录制授权：

1. 先做 30–60 分钟正常使用验收，覆盖多次 Home/Dashboard 切换和 Stop → Start。
2. 通过后再按实际问题场景做 2–4 小时日常使用观察；如需游戏、睡眠唤醒或远程连接场景，提前确认范围。
3. 记录进程 CPU/内存、磁盘增长速度、采样间隔与丢样、UI 响应、会话收尾及新异常日志。
4. 根据实测确定存储配额、保留期限和开销阈值，不凭空承诺固定容量或性能。

验收标准：样本持续推进、会话正常收尾、无新增未处理异常、无持续无界资源增长；阈值依据测量制定。无法复现整机问题时只报告本次未复现，不宣称问题消失。

边界：本计划不自动启动长期录制，不安装后台服务/计划任务，不做压力、强杀、断电或故障注入。录制终态需再次约定；助手不会在对话结束后持续在线监控。

## P3：正式交付与后续故障闭环

- 保留现有 200 项相关回归基线，为权限失败、缺失指标、数据源口径、多适配器、ETW 健康语义和多次录制启停增加测试。
- 生成新的独立测试包、文件清单和哈希，不覆盖已验收包；复核启动入口、版本和备份/回退说明。
- 提供明确的证据导出与采集缺口摘要，保留原始记录，只读重评历史分析。
- 对下一次实际异常，优先关联用户现象、时间线、Windows 日志/转储与有效遥测；证据不足时继续保持未分类。
- 稳定性和采集口径达到约定标准后再考虑正式发布；代码签名、安装方式、自动更新和服务化另行规划，不作为当前诊断的前置条件。

## 推荐的下一次工作单

**先执行 P1 的只读采集诊断，输出 ETW、CPU、磁盘的数据源/权限支持矩阵和最小修复清单，同时补齐 P0 的故障现象说明。**

该步骤不承诺修复所有硬件采集能力。需要录制、管理员对照或系统变更时，先说明必要性、风险、持续时间和结束状态，再取得相应授权。
