# CrashScope 产品体验评审与提升计划

日期：2026-09-21
范围：已交付 0.9.5 UI 测试包的用户截图，以及当前主窗口、首页、事件页、录制页与事件读取代码。
状态：规划评审，不是实施完成记录。本轮仅新增此文档，不修改业务或 UI、不启动程序或录制、不重新运行构建测试。
本文路径相对于 CrashScope 仓库根目录。

## 一、产品判断

用户反馈“还不错”，说明当前精致专业的视觉方向获得初步认可，应保留色板和基础组件，不再整体推翻。下一阶段从外观统一转向任务闭环。

建议产品定位：**低打扰地记录系统运行，在异常之后提供可理解、可追溯的证据，帮助用户决定下一步。**

首页需要回答三件事：现在是否在记录、数据是否可信、出现异常后从哪里开始。它不是所有功能的目录，也不应变成一屏专业计数器。

优先顺序：信任与安全 → 核心任务可完成 → 信息层级和发现性 → 视觉精修。不能用“更惊艳”抵消不准确的状态表达。

## 三、多视角审视

| 视角 | 核心问题 | 设计响应 |
| --- | --- | --- |
| 产品经理 | 用户为什么回来使用，而不只是觉得截图好看？ | 把录制、发现异常、理解证据、导出求助串成闭环；工具功能不抢占主任务 |
| 首次使用者 | 需要管理员权限吗？点开始会做什么？为什么没有数据？ | 简短情境说明；不强迫走教程；按实际缺失能力解释权限，不默认要求提权 |
| 日常监控用户 | 现在是否在记录？最近读数是否还有效？ | 固定录制状态、最近采样时间、温和的缺失/过期提示；不需要反复翻页确认 |
| 故障后的用户 | 刚才发生了什么？哪条记录相关？下一步是什么？ | 人类可读的事件标题、时间语义、按事件直达详情、证据与未知项分离 |
| 高级用户/支持人员 | 能否追溯原始数据，比较会话并安全分享？ | 保留技术详情、ID/路径复制、比较和导出；用渐进展开控制复杂度 |
| 无障碍与可用性 | 不靠颜色、不用鼠标是否也能完成任务？ | 文本状态与焦点提示；键盘打开/返回；关键说明可展开而非仅 Tooltip |
| 性能与可靠性 | 界面是否干扰本职采集，给出过度确定的结论？ | 不新增采样器或装饰性常驻定时器；异步加载按需引入；保留未知状态 |
| 维护与交付 | 每改一页是否都要重做翻译、状态和测试？ | 统一事件展示模型、导航载荷、状态文案和组件；每批独立回归与打包 |

## 四、核心用户旅程

### A. 第一次打开：知道如何开始

首页显示“未录制”，主操作为开始录制。指标统一解释“开始录制后显示实时数据”；没有传感器、权限不足、等待首样本分别说明，不能全部称作未录制。常规权限先运行，只有需要特定能力时提供说明。

验收：无需进入设置即可找到开始入口；开始后立即得到启动中反馈；重复点击不会重复启动；失败后有可理解的原因与重试/查看详情入口。

### B. 日常查看：知道是否值得相信

不只显示数值，还区分最后有效样本与实时值。切换页面或语言不制造误导性零值。若保留上一读数，须标注时间/过期，不用静默冻结的数字伪装实时。

验收：能区分未录制、启动中、录制中且有样本、等待样本、部分不可用、停止中、故障；阈值应依据实际采样间隔配置并写测试，不凭 UI 任意设置。

### C. 异常后回来：从事件直达证据

首页事件卡 → 指定事件详情 → 事实/候选解释/未知项 → 下一步或导出。

验收：打开首页某条事件后展示同一条事件，不是跳到列表第一条；返回时保留列表筛选与滚动位置；缺失记录给出明确反馈。

### D. 分享求助：知道分享了什么

选择事件后启用导出，展示脱敏选项、范围和可能剩余的敏感字段。执行中有进度/工作中反馈，成功后可定位文件；失败可重试，不让按钮永久禁用。不自动上传，导出不改写原始证据。

## 五、信息架构与界面方案

### 1. 首页：状态简报，而非功能大全

建议布局：标题与会话状态 → 紧凑录制状态及主操作 → 三项实时指标 → 最近事件 → 必要的上下文动作。

- 默认 1200×750、100% 缩放、滚动归零时，以能看见状态、三项指标与至少 2 条标准长度事件为目标；数据/长文案不同需实测。
- 900×600 和高 DPI 不强求所有内容一屏；保证可读、可滚动、操作不遮挡。
- 未录制指标区统一解释一次，避免三次重复；仍保留真实的“—”。
- 首屏不再堆完整采集器列表，用简短摘要和“查看采集详情”分层；折叠不隐藏失败事实。
- 首页只显示最近少量事件，更多事件进入完整列表；不是删除历史记录。

### 2. 事件：先可理解，再可追溯

建议示例：

> **异常会话记录**　未分类
> 最后记录：2026年9月18日 09:16　·　查看详情

注意：具体标题依据现有可靠元数据生成。无明确故障证据时，不写“显卡崩溃”或“已确认断电”；若能确认记录来源为恢复流程，再使用“恢复的会话记录”。仅凭 recovered 前缀不能扩展为故障定性。

- 原始目录名进入技术详情，仍可复制；不改磁盘目录或历史 analysis.json。
- 时间按应用语言呈现，本地时区和原始时间可查；由最后心跳推断的时间明确标注。
- 分类翻译有未知枚举回退；证据支持度不是统计故障概率，不将 0 支持度写成“0% 风险”。
- 首页明确单击打开事件；键盘 Enter 同样可用。事件页的多选比较模式另行保持，不让打开行为破坏选择逻辑。

### 3. 导航：围绕任务，不暴露部署架构

- 高频入口：概览、录制详情、仪表盘、事件/诊断。
- Agent 相关入口归入“高级 / Agent”，首次默认折叠但明显可发现；当前所在页面分组自动展开，记住用户展开偏好。
- 硬件、磁盘、网速等归入工具；设置固定底部，不随长导航消失。
- 第一批只做可逆分组、位置调整，不删除页面，不立即合并首页与录制页。
- 后续可将“录制器”改为“录制详情”，首页承担主要开始/停止入口；共享同一状态源，不复制控制逻辑。

### 4. 事件详情：结论必须有证据和边界

顺序建议：记录概览 → 观察到的事实 → 候选解释及支持/反证 → 尚缺信息 → 下一步建议 → 技术详情/导出。

保留既有跨事件分析和比较，减少初始同时展开的大面板。任何建议注明依据和风险；驱动变更、管理员操作、服务安装等不成为默认一键动作。

### 5. 仪表盘：统一图表语言

作为后续迁移项：统一轴文字、单位、时间范围、网格、图例和主题切换；缺失段不连成零线，选中时间点可读取精确值，主题切换不清空历史。当前阶段未逐项审计仪表盘，实施前须核对其数据缓存、事件订阅和图表刷新成本。

## 六、优先级与交付批次

工作量 S/M/L 是相对范围，不是工期承诺；先处理依赖与验证，不以修改文件数量衡量进展。

| 批次 | 优先级 | 范围 | 依赖/成本 | 完成判定 |
| --- | --- | --- | --- | --- |
| A：事件可读与直达 | P0 | 统一标题/分类/时间展示；首页直达指定事件；未选记录禁用导出；中英文兜底 | 展示模型、事件导航载荷，M | 正确打开、正确返回、无错误定性；自动测试+真实点击验收 |
| B：状态可信与反馈 | P0 | 区分未录制/等待/过期/失败；读取失败不冒充无事件；操作反馈 | 状态与读取结果契约，M–L | 故障注入及状态转换测试；证据文件不被改写 |
| C：首页/导航减负 | P1 | 紧凑状态区、减少重复提示、设置固定、高级分组 | 保留导航 ID 与控制逻辑，M | 最小窗口可达，默认首屏目标，中英文/键盘验收 |
| D：诊断和图表体验 | P1 | 事件详情重排、证据与下一步、图表主题和无数据语义 | A/B 基础；图表单独审查，L | 样板页先确认；切换不丢历史；相关交互回归 |
| E：全局打磨 | P2 | 各页字号、弹层、提示、焦点、必要的轻量动效与状态保存 | A–D 稳定，M | 全页状态矩阵与性能基线对比 |

推荐下一轮仅交付 A，不同时扩展所有页面。B 紧随其后；若 A 触及读取失败处理，可单独拆为安全补丁，不把数据层风险混入纯视觉变更。

## 七、工程落地建议

- 创建纯展示映射（例如 IncidentPresentation）：从 IncidentInfo 映射 Title、ModeLabel、TimeLabel、时间来源和稳定记录 ID。首页与事件页复用，不在多份 XAML/C# 拼接重复文案。
- 导航传递稳定事件 ID/受验证的内部记录引用，不使用列表下标；事件页负责选中与聚焦。不要接受任意用户文本作为磁盘路径。
- 对事件读取结果区分成功条目、跳过数和可展示错误；没有权限/解析失败与空列表不同。避免每条坏记录弹窗轰炸。
- 先测量同步加载在 0/10/100/1000 条合成数据下的耗时，再按需缓存/后台加载/虚拟化；后台结果发布前校验页面生命周期，避免离开后刷新旧页面。
- 复用现有采样事件，不为了首屏加入一套新采集逻辑；不更换框架，不重写诊断评分，不增加遥测上传。
- 主题与语言切换不丢选择、滤镜、滚动位置和历史数据；保留标题栏命中与图标/文本分离修复。
- 保持可独立回退的提交边界：展示映射/单测 → 导航与事件动作 → 布局 → 真实交互验证 → 新独立包。

## 八、验收与衡量

### 建议体验目标（待验证，不是已有成绩）

- 首次用户在 5 秒观察后能说清“是否录制、数据是否就绪、下一步按钮在哪”。
- 从首页一条事件到该条详情 1 次激活；已有选中事件到导出 1 次操作进入保存流程，不把系统文件对话框计入。
- 关键操作按下后约 200ms 内出现忙碌/启动中反馈；耗时任务不冻结 UI。实际阈值以目标机测量为准。
- 常用导航不依赖猜测或找到隐藏的折叠项；设置在允许最小尺寸始终可达。
- 不显著增加后台 CPU/内存和图表刷新成本；先记录旧版本相同场景基线，再设允许回归预算，不虚报指标。

### 验收矩阵

- 中英文 × 深浅主题 × 100%/125%/150% 实际 DPI × 默认/最小窗口。
- 未录制、启动中、等待采样、正常录制、部分缺失、过期样本、停止中、故障。
- 事件 0/1/多条、未知枚举、长标题、不同时间偏移、缺失/损坏分析文件、记录加载中。
- 鼠标与键盘打开事件、返回、选中/比较、导出成功/失败；按钮焦点可见且不会仅靠颜色表达状态。
- 构建、选定回归、新增展示/导航/状态测试、真实 WPF UI 自动化或记录完整的手工 smoke。
- 源 XAML 隔离渲染仍用于快速视觉检查，但不替代真实业务事件绑定和发布包验收。

### 轻量用户验证

招募普通使用者与排查经验用户各 2–3 人（若可获得），完成“开始记录、找到最近记录、解释是否确诊、导出脱敏包”四个任务；记录完成率、误解点、无效点击与简短评分。样本仅用于发现问题，不包装成统计结论。不采集真实事故文件或身份信息，不默认增加线上埋点。

## 九、明确不做

不重做整套风格；不堆玻璃/发光效果；不伪造曲线或健康评分；不把分类支持度当概率；不隐藏诊断能力；不自动修复驱动/提权/上传；不为查看新版中断现有录制。
