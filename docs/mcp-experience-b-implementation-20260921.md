# 批次 B：可信状态与读取失败反馈

日期：2026-09-21
范围：`docs/mcp-product-experience-plan-20260921.md` 批次 B；保留批次 A，不扩展到 C–E。

## 实施内容

### 采样与录制状态

- 新增 `src/CrashScope.Desktop/LiveSamplePresentation.cs`，将生命周期、当前会话匹配、采样年龄与数值展示分离。
- 首页区分未录制、启动中、停止中、故障、等待采样、新鲜与过期；停止、故障和过期时不把旧数值呈现为实时值。合法的 0 不视作缺失，缺失值保持破折号。
- 最新快照由 AppService 保存；页面导航及语言切换不重置采样年龄。年龄采用接收时年龄加单调时钟增量；接收时为负年龄的异常样本保持不确定，直到被新样本替换。
- 过期阈值为 `max(5 秒, 3 × 实际采样周期)`，这是展示容忍度，不是采集故障判据。RecorderEngine 仅公开原有 SampleInterval 并复用它，没有改变采样节奏、诊断算法、评分或记录格式。
- “样本新鲜”不代表所有采集源健康；缺失指标明确不可用，既有采集源状态继续保留。不新增未经证实的整体健康判断。
- 新增 `RecorderOperationGate.cs`，首页和录制页的启停操作提供忙碌反馈、互斥与错误反馈；耗时操作移到后台，失败后释放门闩以便重试。未迁移托盘旧启停入口。
- 首页时效计时器仅在页面加载且展示录制状态时运行；录制页在卸载时停止计时器并退订事件。

### 事件读取

- 新增 `IncidentCatalogReader.cs`，读取结果包含有效记录与结构化问题，区分真正空列表、部分失败、全部失败和根目录不可访问。
- 根目录尚不存在仍视为无记录；权限或 I/O 失败不是空列表。缺少 analysis.json、损坏 JSON、权限不足、读取失败、重评估异常均进入问题列表。
- 单条损坏不丢弃其他可读记录；仍按最后心跳时间倒序，仍调用原只读重评估逻辑。缓存沿用文件修改时间与长度标识，未引入文件内容哈希或磁盘监视器。
- 首页和事件页异步读取，显示加载、重新读取、持久警告和可展开明细。明细最多展示前 20 项，摘要保留全部失败计数。
- 事件页读取期间禁用选择、比较和导出；选择正常记录不会擦除部分失败警告。卸载后的迟到响应不更新页面，失败后允许重试。
- 直达事件的目标 ID 在读取失败后保留，重试成功可恢复目标；仍不以第一条记录替代找不到的目标。保留批次 A 的返回恢复、稳定 ID 与导出互斥行为。
- 兼容的 GetIncidents 仍供 Dashboard/Timeline 使用，只返回可读条目；本批次未为这些次级页面补齐异步读取及错误展示，也未宣称全应用覆盖。

## 建议用户验收

1. 在方便切换版本时，确认未录制状态不显示旧实时值；开始录制观察启动中、等待采样、采样到达后的数值与时间。
2. 观察有缺失来源的机器，确认破折号不会变成 0，采样新鲜不会被理解为所有来源正常。
3. 仅在备份后的测试数据环境检查损坏/缺失分析文件、根目录权限失败及修复后重试，切勿改动原事故用于试验。
4. 从首页直达指定事件，检查读取失败后重试、返回首页位置、中英文与深浅主题；观察真实最小窗口和实际 DPI。
5. 正常停止后检查旧数值消失、按钮恢复；记录任何启停卡顿或错误，不强制结束正在持久化的宿主。
